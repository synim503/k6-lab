Свои графики попадают в HTML, PDF и Word-отчёт каждого запуска этого скрипта, после стандартных. Вставьте PromQL и дайте графику имя; запросов на одном графике может быть несколько (например, CPU и память сервера на одной шкале). В запросе можно использовать {run_id} (метка test_run_id запуска) и {range} (окно для rate/increase, например 45s). Ряды рисуются по меткам результата, в легенде — Last / Mean / Max. Пример: sum(rate(http_reqs_total{test_run_id="{run_id}"}[{range}]))
Импорт дашборда Grafana
Вставьте JSON дашборда (Grafana → Dashboard settings → JSON Model или Share → Export → Export as JSON) или загрузите файл. Каждая панель с запросами Prometheus станет графиком отчёта: имя — заголовок панели, подписи — legendFormat, единицы — из панели. Переменная теста ($testid, $run_id…) заменяется на {run_id}, $__interval / $__rate_interval — на {range}, остальные переменные — их текущим значением (для «All» — любое). Панели не с Prometheus и без запросов пропускаются; график с тем же именем обновляется. Если ваш дашборд привязывает запуск по другой метке, поправьте запросы ниже в списке.
Если выбран файл, используется он, а не текст.
График с уже существующим именем будет обновлён. Если запрос возвращает несколько рядов, к подписи добавляются их метки.
Переменные
В запросах переменная пишется как $имя или ${имя}, при построении отчёта подставляется её значение. Значение {run_id} — идентификатор запуска (так задаётся переменная теста), {range} — окно для rate/increase. Для регулярных выражений (=~) значение может быть .* или a|b. При импорте дашборда Grafana сюда попадают его переменные; уже заданные не перезаписываются.
